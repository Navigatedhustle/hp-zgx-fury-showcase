Make the operating decision

Local inference can reduce reliance on metered cloud APIs for these workloads. Hardware, energy, administration and software still have costs. Assess utilization, data handling and support requirements with your team.

Move toward deployment by validating outputs, access controls, capacity and recovery with your own approved test data.

Product specifications and this demonstration host

HP’s advertised coherent memory combines different memory resources; it is not all GPU VRAM. This host reports 256703 MiB HBM and 743.65 GiB system RAM on Ubuntu 24.04 ARM64. These are host observations, not a promise for every product configuration.

Liquid cooling and airflow descriptions are product design information, not measurements of this demo’s noise, temperature or sustained thermal performance.

Shared local AI

Four tasks. One shared system.

Let a development build run while other visitors ask, create and explore. Separate browser sessions keep their own application state; shared capacity stays bounded.

  1. Start an automatic short travel build in Agent Factory.
  2. While the build is generating, submit the Atlas question, a three-slide brief and an image prompt in separate tabs or devices.
  3. Inspect each output. Use the operator view to examine measured model activity and resource use. Submission at similar times alone does not prove execution overlap.

Capacity: one Factory build globally, up to two development calls, four gateway admissions with an Atlas reserve. Image generation and slide authoring each have bounded queues. Other sessions may wait or receive a clear capacity message. No unlimited-user or guaranteed-latency claim.

Presenter guide

Show the work.
Explain the decision.

A ten-minute conversation

  1. Discover: “Which task could your team keep local?” Choose a catalog example.
  2. Demonstrate: Show the input, progress, output and supporting evidence.
  3. Share: Start the four-task scenario; compare outputs and measured activity.
  4. Discuss: Map system placement, model operation and human review to the customer’s environment.

Factory duration varies. Allow several minutes for a short build; complete travel is a longer technical demonstration.

Prepare and recover

Before presenting, check readiness in the operator view and confirm the sample data. Keep existing work open.

If a task queues, explain shared capacity. If a request fails, inspect its message and retry your own work. Reconnect Factory in the same browser to retain ownership; use Stop only for your run.

For service faults, use ./launch.sh status and ./launch.sh diagnostics. An operator can use ./launch.sh recover agent after establishing that work is idle. Do not restart all services during another visitor’s job.
