Build Aster Journeys, a real local DEMONSTRATION travel product. No live bookings, payments or external network. Python stdlib + SQLite backend, vanilla HTML/CSS/JS frontend. All persistence is server SQLite at db_path. Each handle(request,db_path) runs in a fresh networkless process. Close connections and COMMIT writes. Native dict response {status:int,body:dict}; request={method,path,body,headers}. Never JSON encode body. Browser calls await window.furyApi(method,path,body={}) -> {status,body}; no fetch/libraries. The trusted bridge stores returned login/register body.token and sends request.headers.authorization='Bearer '+token; frontend need not store tokens. All user/private and admin authorization MUST be enforced by backend, never trust user_id/role in body. Use salted hashlib.pbkdf2_hmac passwords, secrets.token_urlsafe sessions persisted in SQLite with expiry. Seed demo administrator admin@example.test / DemoAdmin2028! (label public demo credentials); registration ALWAYS creates ordinary user. Invalid input400, unauthenticated401, forbidden403, missing404, conflict409, created201, successful GET/update/delete200. Nonempty body.error on errors. No raw tracebacks, password hashes or session tokens in lists.
Architecture uses these flat files: db.py exports connect(db_path) initializing schema and deterministic inventory, auth.py exports user(conn,request) -> dict or None and routes(conn,request) -> response or None, catalog.py/private.py/reservations.py each routes(conn,request) -> response or None. backend.py handle opens with contextlib.closing(db.connect(db_path)) as conn, conn: dispatches auth,catalog,private,reservations; returns404 if no route. modules import db/auth as needed. Every row factory is sqlite3.Row. Every routes(conn,request) MUST first check its owned path and method and return None for unrelated requests BEFORE authentication. In particular private.routes must not intercept /quote or unknown routes with401. All schema in db.py: users(id,email UNIQUE,password,salt,role), sessions(token PRIMARY KEY,user_id,expires), listings(id,name,city,country,description,price INTEGER EUR/night,capacity INTEGER,active INTEGER), favorites(user_id,listing_id,UNIQUE(user_id,listing_id)), itineraries(id,user_id,title,notes), reservations(id,user_id,listing_id,check_in,check_out,party,total INTEGER,request_key,UNIQUE(user_id,request_key)). Use parameterized SQL. No Python global persistence. Backend handles invalid JSON types safely.
API contract:
GET /health -> {ok:true,demo:true}.
POST /register {email,password} -> {token,user:{id,email,role}}; password min10 max128, normalized email max160 valid; duplicate409.
POST /login same response, invalid credentials401. POST /logout deletes bearer session ->200. Logout is idempotent: repeating logout with an already revoked bearer may return200 or401. Verify actual revocation with GET /me and protected GET /favorites returning401 for the revoked token, not by prescribing a repeated-logout status. GET /me -> {user} or401.
GET /listings accepts a native dict body EVEN THOUGH its method is GET; POST /listings is not a supported route and returns404. Example handle request: {"method":"GET","path":"/listings","body":{"sort":"price_desc"},"headers":{}}. GET /listings body filters {q,city,sort:'price_asc'|'price_desc',page:1,page_size:6,max_price,party} -> {listings:[...],total,page,page_size}; server filter case-insensitive name/city/country q, city exact, max_price finite positive, party integer1..8, page_size1..12. Defaults page1/page_size6. GET /listings/{id} -> {listing}. Seed >=18 rich fictional properties across Lisbon, Kyoto, Copenhagen, Edinburgh, Porto, Ljubljana, with varying numeric EUR prices and capacities. All labelled demo. No fake ratings/availability.
GET /favorites -> {favorites:[listing records]} authenticated. POST /favorites {listing_id} ->201 (idempotent200 allowed). DELETE /favorites/{listing_id} ->200. Only own records.
GET /itineraries -> {itineraries:[{id,title,notes}]}. POST /itineraries {title,notes} ->201 {itinerary}. PUT /itineraries/{id} {title,notes} ->200 {itinerary}. DELETE same ->200. Authenticate; cross-user IDs404. Trim title1..100 notes<=4000.
POST /quote is PUBLIC: never require a session or bearer token. Anonymous requests must reach validation and return200 for valid input,400 for invalid input. POST /quote {listing_id,check_in,check_out,party} -> {quote:{listing_id,check_in,check_out,party,nights,nightly,total,currency:'EUR'}}. Real YYYY-MM-DD dates, check_in >= today, checkout>checkin, nights<=30, party integer1..capacity. Numeric finite fields; reject bool. Price comes ONLY from DB, total=nightly*nights (no invented fees). Unknown/inactive listing404.
POST /reservations same fields plus request_key string8..100 ->201 {reservation:{id,listing_id,check_in,check_out,party,total}}; authenticated; recompute quote server-side ignore supplied total. Duplicate request_key per user409. GET /reservations -> {reservations:[own records]}. GET /reservations/{id} ->{reservation}, own only otherwise404. Demo inventory permits concurrent illustrative reservations; do not imply live availability.
GET /admin/reservations -> {reservations:[sanitized records with user_id]}; GET /admin/listings -> {listings:[including inactive]}; PUT /admin/listings/{id} {price,active} ->{listing}. Admin only403 for ordinary users,401 anonymous. Price integer1..10000, active integer0/1. No arbitrary SQL/routes/files.
