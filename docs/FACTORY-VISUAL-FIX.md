# Factory visual acceptance repair

The immutable v2.3.0 release failed three fresh baseline attempts when Visual acceptance proposed HTML edits with quote styles that differed from the source. The owner explicitly authorized a narrow repair and a baseline on the corrected commit. This branch does not replace or move the v2.3.0 tag or its published archives.

Visual acceptance now requests a bounded repair plan from the already loaded DeepSeek Technical Lead. Its actual model is displayed in task/call state, recorded in the model-selection event and counted by the gateway. Other Factory tickets, model settings, admission limits, sandbox, review flow and the two-attempt limit are retained.

The model selects existing generic list containers and writes small CSS overrides. The coordinator compiles list roles onto the existing elements, including asynchronously rendered empty and populated children. Original HTML, rendering functions, listeners, IDs, API calls and existing stylesheet bytes are preserved. The supplied compiler is disclosed in generated source comments; it is an accessibility repair helper, not a supplied application or a substitute for failed generation. CSS remains model-authored. Plans cannot select arbitrary elements or modify backend/QA source.

The independent browser criteria remain the same: actual generated backend, bookings, duplicate feedback, inventory filtering and sorting, desktop/mobile layout, and local axe WCAG checks. Visual diagnostics now report both viewports before returning, including the flex parent of overflowing elements. A repair sees the current failure after an applied candidate; rejected proposals retain the original diagnostics.

Three real pre-fix snapshots passed replay through local inference, the actual generated backend, desktop/mobile empty/populated checks and sandbox tests. Each passed on its first proposal in 13.77, 16.44 and 12.20 seconds. Raw snapshots, generated artifacts and session data remain outside publication. These replays verify the repair; they are not a replacement for fresh Live-build and four-workload acceptance. Their results belong in the separately recorded corrected baseline before Gate 0 can pass.

## Owner-authorized simplification after the Phase 1 stop

The owner authorized continuation with simpler, functional interactions after another Visual failure. The failing populated reservation date had been hidden behind the first element in axe's color-contrast violation. Diagnostics now inspect every violating element, deduplicate repeated element classes, and collect both empty and populated states before requesting repair. The original accessibility criteria still fail on any violation.

Visual repair now returns structured selector/property/value declarations. The supplied compiler serializes CSS punctuation and override priority, avoiding model-authored quotes where semicolons belong. Values and selectors are bounded, remote image URLs and malformed declarations are rejected, and repairs cannot hide controls. Only the artwork fallback can be hidden, scoped to the presence of the supplied artwork variable. Original application logic and source bytes remain preserved; the existing independent browser, generated backend, booking, conflict, inventory and sandbox checks still run. The two-proposal limit and all other workers remain unchanged.

The newly failed snapshot passed the updated real local-model replay on its first proposal in 14.93 seconds. This is repair evidence, not a substitute for fresh concurrent Factory qualification or final V3 hardware acceptance.

The final bounded schema offers only selectors present in source and a small value palette, with deterministic Visual sampling. It cannot request media-query fragments, make text transparent or collapse controls. Both recent failed snapshots passed the final real replay: 15.64 seconds on one proposal and 26.46 seconds including one ordinary repair. Those repair costs are retained.

## V3 rendered artwork check

A loaded image can still contribute no pixels beneath an opaque fallback. The real-browser Visual gate now finds matching supplied image/CSS artwork areas, captures their actual crops with and without the image contribution, and restores the exact original inline style attribute in a finally block. Primary hero areas take priority: visible artwork in a separate property card cannot mask an occluded hero. At least one substantial artwork area must change at least 0.5% of crop pixels above a small difference threshold. A useful translucent gradient passes; a fully opaque overlay fails with selector/stacking diagnostics. Legacy runs without pinned artwork retain their original environment. Existing generated versions are never edited.

The bounded Visual model can select conditional hiding of `.hero-fallback` or repair position/z-index. The compiler permits hiding only that fallback and only when supplied artwork is present; other controls/content cannot be hidden. Model sampling, two-proposal bound, independent axe/mobile checks, real booking/conflict/filter/sort checks and sandbox remain in force. A real browser regression covers opaque overlay rejection, gradient acceptance, CSS background contribution and exact style restoration.
