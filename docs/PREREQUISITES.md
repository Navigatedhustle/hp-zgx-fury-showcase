# Tested host and prerequisites

The measured workstation runs Ubuntu 24.04.5 LTS, Linux 7.0.0-1019-nvidia-64k, aarch64, Python 3.12.3, 494.15 GiB usable physical Grace RAM (NUMA node 0; Linux aggregate 743.65 GiB includes HBM node 1), NVIDIA GB300 with 256703 MiB HBM, driver 595.99.02 and CUDA compilation toolkit 13.3.33. These existing host components are shared by same-host clean-install testing; they are not distributed or installed by this project. A different driver/toolkit combination has not been verified.

The full profile requires this GB300 capacity and conservatively checks at least 480 GiB physical Grace memory, 700 GiB combined Linux-visible capacity and 350 GiB free disk at initial setup. It checks 40 GiB remaining after setup; Factory independently refuses generation below 20 GiB. Sustained artifacts consume disk (the historical hour test produced about 1.96 GiB). Downloaded model files total about 227.566 GiB; dependency wheels, environments, Chromium and JIT caches add tens of GiB. The historical live profile used about 243137 MiB with about 12 GiB directly reported free. Its 176 GiB DeepSeek engine budget fell to 4211 MiB free in the fresh-install concurrency test after cold initialization. The tested public profile reduces that nominal engine budget to 168 GiB, retaining 16K context/one sequence and all Qwen/gateway concurrency settings. Its complete four-way test retained at least 13451 MiB free, above the 10 GiB target. Never infer usable free memory solely by subtracting used from total: NVIDIA reserves additional memory.

Host prerequisites: Python 3.12, curl, CA certificates, tar/xz, gcc/g++, make, bubblewrap (`bwrap`), util-linux (`prlimit`, `flock`), apt-get/dpkg-deb, libsndfile1, a working NVIDIA driver, and `/usr/local/cuda/bin/nvcc`. Python venv/ensurepip is not required: the pinned local uv binary creates environments. Bootstrap extracts Python development headers locally from the configured Ubuntu repository without installing system packages. OS package repositories and their security updates remain the recipient's responsibility.

If tools are missing, an administrator can install the ordinary Ubuntu build/runtime packages, for example `sudo apt-get install curl ca-certificates xz-utils build-essential bubblewrap util-linux libsndfile1`. Do not replace working GPU drivers or change kernel configuration as part of this setup. CUDA toolkit/driver provisioning belongs to the workstation administrator. Bootstrap never runs sudo.

Playwright installs Chromium into `.cache/ms-playwright`. Missing browser system libraries are reported by Playwright. An administrator can inspect `.venv/bin/python -m playwright install-deps --dry-run chromium` and install the needed OS libraries. The launcher does not run this broad OS installation itself.

Bubblewrap must support unprivileged namespaces. Ubuntu AppArmor policy can restrict this even if `bwrap` exists. Preflight exercises a real networkless namespace. Ask the administrator for a narrowly scoped bubblewrap policy if blocked; never disable AppArmor globally or bypass the sandbox. Generated Python has no unsandboxed fallback.

Used ports: 8000 Qwen, 8100 DeepSeek, 8001 gateway, 8200 Atlas, 8202 ASR, 8204 TTS, 8765 slides, 8501 Factory, 8800 images, 8080 dashboard. The optional reference server uses 8510. Inference workers also use ephemeral local sockets. A foreign listener is a blocker; stop its owning installation through its own manager. Launch never adopts an unrelated registry.

Setup errors: rerun `./launch.sh setup`. Downloads use immutable revision/file hashes and retained partial metadata. If verification fails, remove only the named corrupt model file and rerun. Cold model compilation can take several minutes and each model readiness wait is bounded. Diagnose `logs/text.log`, `logs/lead.log` and the reported failure before restarting. Preserve outputs before manually clearing runtime directories.

Cold first initialization can take tens of minutes because FlashInfer/DeepGEMM compile and autotune GB300 kernels. The lead model readiness wait is bounded at 60 minutes; a failed process is detected immediately. Watch `logs/lead.log` for detailed progress; no manual compilation commands are required. Warm-cache restart timing is a separate measurement.
